slate.http.client

HTTP Client, execution engine, and @nogc transfer boundaries over libcurl easy handles.

Discussion

This module provides the value-type Client (UB-1) and configuration model ClientConfig. It implements a clean architectural memory split:

  • Cold Configuration Path (GC Allowed): Creating ClientConfig, parsing URLs, configuring headers, and high-level string helpers may allocate memory via D's GC.
  • Hot Execution Path (Strictly @nogc): Single-transfer execution (perform(req, buffer) and performStream), C callbacks, and range consumption operate with @safe @nogc guarantees, never allocating heap memory or invoking GC runtime (UB-4, UN-1).
All C ABI callbacks are defined as extern(C) function ... @nogc nothrow receiving typed context pointers (void* userdata), ensuring no D GC delegates cross the C boundary. Handle lifecycles and error recovery are strictly guarded by RAII scope(exit) cleanup semantics to prevent handle and memory leaks (UN-3).
