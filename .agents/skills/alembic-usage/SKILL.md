# Alembic Usage Skill

This project uses Alembic for database migrations with async SQLAlchemy.

## Setup
Migrations require a sync PostgreSQL driver:
```bash
cd backend
uv sync --group migrations
```

## Common commands
```bash
# Create a new migration (autogenerate from model changes)
cd backend
uv run alembic revision --autogenerate -m "description of change"

# Apply all pending migrations
uv run alembic upgrade head

# Roll back one step
uv run alembic downgrade -1

# Roll back to a specific revision
uv run alembic downgrade <revision_id>

# Show current revision and history
uv run alembic current
uv run alembic history
```

## Workflow
1. Edit or create SQLAlchemy models in `backend/app/domains/<name>/models.py`
2. Import the model in `backend/app/db/__init__.py` so Alembic discovers it
3. Run `alembic revision --autogenerate -m "..."` to generate the migration
4. Review the generated migration file in `alembic/versions/`
5. Run `alembic upgrade head` to apply
6. Test the migration works (up and down)

## Important
- Always review autogenerated migrations — they may miss complex changes
- Test both `upgrade` and `downgrade` before committing
- Never edit existing migration files after they've been committed
- The app uses async (`asyncpg+postgresql://`) but Alembic uses sync (`postgresql://`). The config is in `alembic.ini`
